Phase 2: the first live decision

Phase 1 built every part of a decision and proved it against a fake model. Phase 2 connects a real one: a local Ollama server, a queue in front of it, and a memory that carries one exchange into the next. It is done when an agent with five actions decides in under five seconds against a live model, with its telemetry filled in.

One decision, end to end

where each issue sits

Today Agent hands its request straight to a fake provider. Phase 2 puts two new hops between the agent and the model, a queue and the Ollama provider, and adds memory on both ends: recalled into the request, and written after the result.

#89

Request queue and priority

merged, #103

A local model answers one request at a time. Five requests at once took about 3.5 s in the prototype, which puts thirty agents near 21 s. This adds one queue per model connection, shared by every agent using it. Each call can be marked player-facing, the default, or background, and player-facing calls go first. Telemetry records the wait, so a slow answer can be pinned on the model or on the queue.

Done when
  • Background then player-facing queued: the player-facing one is sent next
  • A request cancelled while queued never reaches the provider
  • LatencySeconds excludes the time spent waiting

#90

Short-term memory

merged, #104

The last few exchanges go back into each request, oldest first and within a token budget, so "Now wait here." can follow "Follow me.". Each exchange is stored as the stimulus plus the decision as JSON. What is remembered is the decision the agent actually made, never the model's raw text.

Done when
  • The second request carries the first exchange
  • Past the cap, the oldest exchanges drop whole
  • Two agents from one profile never share memory; failures remember nothing

Rules carried in from measurement

do not change without new evidence

Phase 2 is the first code that talks to a model, so it is where measured settings are easiest to lose by accident.

  • 127.0.0.1, never localhostOn Windows, localhost tries IPv6 first and Ollama listens on IPv4 only. The same tiny request took 2.26 s against 0.14 s (findings, 5 October).
  • Temperature 0, thinking offAppendix A's numbers were measured with greedy decoding and Qwen's reasoning mode off.
  • The schema constrains; it is not readOllama compiles format into the sampling grammar and never shows it to the model: the prompt was 37 tokens with or without it (findings, 10 October).
  • Providers never rewrite a blockTwo of the three regressions the prototype's A/B harness caught were prompt wording changes. Blocks arrive rendered and leave unchanged.
  • One model resident when timingTwo models on an 8 GB card flatten every latency number (hard rule 3). Check with ollama ps before #94's measurement.
  • No accuracy claims from Phase 2A live decision proves the pipeline, not the model's judgement. Accuracy needs an A/B run with a control arm (hard rule 2), which is Phase 4.

Calls made in the issues

open to argument before the code lands

Four choices the build plan left open were settled in the issue text so work could start. Each issue says what to do if building it shows a better answer.

  • #88 · HttpClient over UnityWebRequestThe prototype used UnityWebRequest, which lives in a Unity module the package would have to declare, and CI allows only Newtonsoft. HttpClient needs nothing. The other route is to declare the module and widen the CI rule to Unity's built-in modules in the same PR. Settled: HttpClient, merged in #102. WebGL players are not supported, since HttpClient has no sockets there.
  • #90 · How a remembered exchange is writtenTwo entries per exchange: the stimulus as sent, then the decision as JSON in schema order, sent as a user and an assistant message. The model sees its earlier answers in the form it must give now. The prototype kept only the spoken line, which drops the action.
  • #91 · Which observations the cap keepsFacts passed for this call are kept first, and gathered lines fill the rest in source order. The build plan says only that per-call lines go last in the prompt and that a cap applies.
  • #92 · Two levels of provider config, not threeThe agent's own config, then the project default. DR-013's middle level, a scene override, waits until a demo needs it, which DR-013's revisit clause allows.
