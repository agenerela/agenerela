Every accuracy claim we make has to come from a run like this one: a control arm, the same model, the same machine, the same session.

What the numbers point to

1
Run set-up

The same prompts and model for both set-ups (arm A and arm B), in one session, after a warm-up, with only one model loaded.

2
Five outcomes, not one score

Correct, wrong but legal, contained by a guard, rejected when an action was expected, pipeline error. Each one needs a different fix.

3
Noise check

Differences too small to trust at this number of prompts are marked, so nobody reports an improvement that isn't real.

4
By category

Commands, impossible requests, conversation, situations and events, so accuracy is never measured on chat alone.

5
Failures

The prompts the agent got wrong, with expected vs. actual. “Open” jumps to that decision in the Decision Log.

6
Labels and export

How often our two labellers agreed, and a one-click summary to paste into our findings page.
